# スマホ用Web画面

iPhone等のブラウザで、検索、新規作成、編集、取り込み、差分確認、承認後の反映、履歴の確認を行えます。データは従来のFilters / Diff / History / Backupに保存します。

## 初回の配置

1. `npm test`、`npm run check`、`npm run build`を実行します。
2. 新規導入は通常のインストーラーを利用します。既存導入では更新したインストーラーの`GFM_updateInstalledCode`を実行します。配置先を手動変更するとインストーラーの整合性確認が停止します。
3. **スプシに紐付く運用用GAS**を所有者のアカウントで開き、`GFM_enableWeb`を実行します。インストーラー側では実行しません。
4. 運用用GASを「ウェブアプリ」としてデプロイします。実行ユーザーは「ウェブアプリケーションにアクセスしているユーザー」、アクセスできるユーザーは「自分のみ」です。マニフェストにも`USER_ACCESSING` / `MYSELF`を指定しています。
5. 発行された`/exec` URLをSafariで開き、所有者のGoogleアカウントでログインします。利用URLや個人設定を公開ソースへ埋め込む必要はありません。

初期化はスプシIDをScriptPropertiesに設定し、既存DocumentPropertiesから復旧状態を移行します。プレビューと承認準備は無効化します。再初期化しても古い復旧状態を再読込しません。メニューとWebは共通のScriptProperties・ScriptLockを使用します。スコープは従来の運用用GASと同じです。組織設定で配置が制限される場合も、匿名公開に変更する必要はありません。

## 操作

- 一覧で条件を検索し、対象を開きます。新規作成・編集の「変更を保存」は**スプシだけ**を更新します。
- 「無効」「削除予定」は、反映時にGmail上のフィルターを削除する状態です。行は物理削除しません。
- 「変更確認」で追加・更新・削除と変更前後を確認します。入力エラーは編集画面で修正します。
- 「反映の確認へ」でバックアップを作成・検証します。内容の確認にチェックし、「この変更をGmailに反映」で適用します。
- 確認の期限は15分です。別画面やGmailで設定が変わった場合は再確認が必要です。
- 履歴で日時・結果・エラー・バックアップIDを確認できます。処理済み件数には変更なしも含まれます。

通信が切れても適用を自動再送しません。結果不明の場合は履歴を確認してください。部分完了や復旧が必要な場合は[復旧手順](recovery.md)を参照してください。

Webの保存は読み込んだ版と一致するか確認します。ただし、直接のセル編集はGASのロックに参加しません。Webで保存・反映する間は直接編集を避けてください。Sheets APIに条件付きセル更新のトランザクションがないため、外部編集との極めて短い競合区間を完全には排除できません。

## iPhone・更新

Safariで利用URLを開き、共有メニューの「ホーム画面に追加」で入口を置けます。Googleログインが必要な通常のWeb画面です。

更新は再ビルドしたインストーラーの`GFM_updateInstalledCode`で行い、デプロイ管理から**既存のWebデプロイ**を新しいバージョンに更新します。同じデプロイならURLを維持できます。

## デザイン・ローカル検証

[デジタル庁デザインシステム](https://design.digital.go.jp/dads/)のカラー、文字、ボタン、入力欄、結果表示を参考にした独自HTML/CSSです。デジタル庁のロゴは使っていません。完全準拠や認証を表すものではありません。UIの外部CDN依存はありません。

`node scripts/preview-web.js`で合成データのプレビューを起動し、`http://127.0.0.1:4179/`で操作できます。実際のWebコントローラーとSheetsアダプターにテスト用Googleサービスを接続し、実アカウントは変更しません。このサーバーはGASへ同梱されません。

通信断で結果不明になった場合は、実行IDと「保存済みの結果を確認」「この実行の履歴を確認」を表示します。未確認の結果はサーバーに保存し、再読み込み後にも表示します。新規作成の再送防止情報は最近20件を保持します。古い未保存画面の保存は拒否されますが、1日当たりの作成件数制限ではありません。
