# Gmail Filter Manager 設計
GAS V8 / JavaScript。外部依存ゼロ。Node.jsの標準テストランナーで同一ソースを検証する。初回導入は[インストーラー](installer-design.md)がスプレッドシートとコンテナバインドGASを作成する。

## 境界
- Core.js: 安定JSON、比較、フィルター↔行変換、入力検証、差分。
- Sync.js: import/preview/prepare/apply/verify、バックアップ、実行ジャーナル。
- Sheets.js: 5シート、テキストの数式対策、永続状態、追記と読み返し。システム列は行メタデータを指定してSheets拡張サービスで一括更新。
- Gmail.js: 拡張Gmailサービスの小さなラッパー。本文アクセスなし。
- Menu.js: 手動カスタムメニューとYes/No確認。確認を跨いでロックを保持せず、確認後の再ロック内で再照合。

## 安全な同期
previewはFilters設定、全Gmailフィルター、ラベル/転送先、再計算した計画をハッシュ化しDocumentPropertiesに保存する。Diffは表示専用。Apply準備で再照合とバックアップ読み返しを行い、ダイアログ後に再ロック・再照合する。
各API書き込みの直前に操作ジャーナルを保存し、応答後にチェックポイントを更新する。CREATE応答不明は再試行せず停止。次回実行はGmail再取得による照合・ID復旧のみ実施し、再Dry Runと再承認が必要。REPLACEは新ID保存後に旧ID削除。作成失敗なら旧IDを残す。
4分の予算と最大50変更/回で安全停止し、次回のDry Runから続行する。1000件上限で削除先行しない。
承認時のFilters / Labels定義と対象キーを固定する。新しいSHEET_AUTHORITATIVE承認ではGmail側の差分を現在状態として読み、対象範囲をスプシの定義へ上書きする。一巡後の差分を保存・表示する。シート定義と行の関連付け、結果不明の作成は引き続き保護する。方針マーカーのない古い承認では、Gmail全体の変化も停止条件とする。
行更新のAPIはspreadsheetsスコープを必要とする。currentonlyでは利用できないため、OAuth権限は拡大するが送信先は現在のコンテナIDだけに制限する。
未知フィールドは原本JSONに保持し、変更が必要な再作成だけブロック。NOOPと明示削除は未知フィールドでも可能。
未確定事項の既定はエラー/保存/非削除/単一所有者。復元は独立した手動手順とし自動実装しない。

## Issue #5: 保存済みフィルタージョブ

Web/Menuの承認済み適用は `Jobs.accept` が短時間で受け付け、Runtimeが保存済みブックと所有者を確認して専用トリガーから `Jobs.run` を呼びます。承認済みの行・差分・状態はシートの不変データへ保存し、小さな実行ヘッダーと期限だけをPropertiesで管理します。CREATE / LABEL / DELETE / PATCH / COMMITを永続化し、API・メタデータ応答消失時はGmailとシートから照合します。各段階、選択範囲・編集検出、参照のバッチ更新、ログ制御の詳細は[バックグラウンドジョブ](background-jobs.md)を参照してください。既存の同期コントローラーは互換性と合成比較用に残し、本番Webの適用はJobsを通します。
